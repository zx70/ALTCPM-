SKILL: CPM22 TO CPM14 PORTING ANALYZER
VERSION: 0.2
------------------------------------------------------------------

PURPOSE
-------

Analyze CP/M assembly source code and identify
constructs that may prevent execution on
CP/M 1.4 systems.

This skill does NOT automatically modify source.

Its purpose is to classify findings as:

  [OK]      Already compatible
  [CHECK]   Requires verification
  [WARN]    Likely CP/M 2.2 dependency
  [INFO]    Useful information

------------------------------------------------------------------


FUNDAMENTAL CONCEPTS
--------------------

CP/M 1.4 and CP/M 2.2 share most basic
file operations but differ in:

  - BDOS function availability
  - random file access support
  - disk parameter discovery
  - directory geometry handling
  - BIOS data structures

Many CP/M 2.2 programs assume services
not available under CP/M 1.4.


COMPATIBILITY ANALYSIS RULE
---------------------------

When a CP/M 2.2-specific construct appears
inside code explicitly excluded from CP/M 1.4,
it shall NOT automatically be reported as a
compatibility problem.

Examples:

  IF !CPMV1
      ...
  ENDIF

  IF CPM22
      ...
  ENDIF

  CALL BDOS
  CPI 20H
  JNC CPM22_PATH

and a corresponding CP/M 1.4 path exists.

In such cases the CP/M 1.4 implementation
must be evaluated before issuing warnings.

RULE A1 - CP/M VERSION DETECTION
--------------------------------

Pattern:

  MVI C,12
  CALL BDOS

Purpose:

  Read operating system version.

Notes:

  Used to select CP/M 1.x or CP/M 2.x
  execution paths.

Action:

  Verify that a CP/M 1.4 fallback path exists.

Classification:

  [CHECK]


------------------------------------------------------------------

RULE A2 - BDOS FUNCTION 31
--------------------------

Pattern:

  MVI C,31
  CALL BDOS

Purpose:

  Obtain Disk Parameter Header (DPH)
  information.

Notes:

  This function is available in CP/M 2.x.

  CP/M 1.4 systems generally require a
  different mechanism.

Action:

  Verify existence of a CP/M 1.4 fallback.

Classification:

  [WARN]

RULE A6 - RANDOM FILE ACCESS
----------------------------

Pattern:

  Accesses to:

    FCB+21H
    FCB+22H
    FCB+23H

  or BDOS random-access functions.

Purpose:

  Detect dependence on CP/M 2.x random
  record facilities.

Action:

  Verify whether an alternate CP/M 1.4
  implementation exists.

Notes:

  The presence of RULE A7 indicators may
  suggest an existing random-access
  compatibility layer.

Classification:

  [WARN]

RULE A7 - EXTENT MANAGEMENT
---------------------------

Pattern:

  Direct manipulation of extent fields.

Examples:

  OPEN
  CLOSE
  MAKE

used while changing extent numbers.

Purpose:

  Detect explicit CP/M 1.4 extent handling.

Notes:

  Such code is commonly written as a
  compatibility layer for CP/M 1.x.

Action:

  Usually indicates existing portability work.

Classification:

  [INFO]


------------------------------------------------------------------

RULE A8 - EXISTING CP/M 1.x COMPATIBILITY
-----------------------------------------

Pattern:

  IF CPMV1

  IF CPM14

  runtime dispatch to CP/M 1.x-specific code

Purpose:

  Detect pre-existing CP/M 1.x support.

Notes:

  CP/M 2.x constructs found inside a
  CP/M 2.x-only branch must not be reported
  as compatibility failures when an alternate
  CP/M 1.x implementation is present.

Action:

  Evaluate both paths before issuing warnings.

Classification:

  [INFO]

RULE C4 - SEARCH FIRST/NEXT RETURN VALUE ASSUMPTIONS
----------------------------------------------------

Pattern:

  Tests on register A after:

    BDOS 17
    BDOS 18

Examples:

  CPI 4
  JC ...

  ANI 3

Purpose:

  Detect assumptions about Search First /
  Search Next return values.

Notes:

  CP/M 2.x returns values in the range:

    0..3

  representing entries inside the DMA buffer.

  CP/M 1.4 may return values covering the
  directory entry number.

  Programs assuming the range 0..3 may fail.

Action:

  Verify return-value handling.

Classification:

  [WARN]

RULE C6 - DRIVE BITMAP ASSUMPTIONS
----------------------------------

Pattern:

  MVI C,24
  CALL BDOS

  or

  MVI C,29
  CALL BDOS

  followed by bitmap processing.

Purpose:

  Detect assumptions about drive bitmap layout.

Notes:

  CP/M 2.x returns bitmaps covering drives:

    A: through P:

  CP/M 1.4 supports at most:

    A: through D:

  Programs scanning or manipulating all 16 bits

Action:

  Verify bitmap interpretation.

Classification:

  [CHECK]

RULE C7 - DMA SCRATCH AREA DEPENDENCY
--------------------------------------

Pattern:

  Direct access to memory immediately preceding
  the DMA buffer.

Examples:

    DMA-1
    DMA-2
    DMA-3

  or literal references consistent with the
  default DMA area:

    7DH
    7EH
    7FH

Purpose:

  Detect assumptions about internal DMA buffer
  layout.

Notes:

  CP/M 1.4 uses bytes preceding the DMA area as
  temporary storage during disk operations.

  Programs reusing these locations may interfere
  with CP/M 1.4 operation.

Action:

  Verify that the area is not relied upon for
  persistent program data.

Classification:

  [CHECK]

SECTION D - BIOS COMPATIBILITY
==============================

ALTCPM NOTE
-----------

ALTCPM-derived CP/M 1.4 systems may provide BIOS
extensions normally associated with CP/M 2.x.

Examples include:

  - DPH-like structures
  - SELDSK return values
  - sector translation facilities
  - additional BIOS entry points

The presence of such facilities must not be
assumed solely from the operating system version.

Conversely, the absence of a standard CP/M 2.x
feature must not automatically be interpreted as
a compatibility failure.

When evidence indicates an ALTCPM-derived BIOS,
warnings related to DPH handling, SELDSK return
values, sector translation or geometry discovery
should be evaluated against the actual BIOS
implementation rather than the nominal CP/M
version.

Classification:

  [INFO]

RULE D1 - SELDSK RETURN VALUE ASSUMPTION
----------------------------------------

Pattern:

  CALL SELDSK

followed by pointer manipulation such as:

  MOV E,M
  MOV D,M
  LHLD xxxx
  DAD D
  INX H

or equivalent parsing of a returned structure.

Purpose:

  Detect assumptions about the SELDSK return
  value.

Notes:

  CP/M 2.x SELDSK returns a DPH address in HL.

  CP/M 1.4 does not define any return value.

  Programs inspecting structures returned by
  SELDSK are implicitly dependent on CP/M 2.x
  BIOS behaviour.

  See ALTCPM NOTE.

Action:

  Verify presence of a CP/M 1.4 alternative or
  confirm equivalent BIOS support.

Classification:

  [WARN]

------------------------------------------------------------------

RULE D7 - SELDSK DRIVE RANGE ASSUMPTION
---------------------------------------

Pattern:

  MVI C,n
  CALL SELDSK

where n > 3

or equivalent drive-selection logic.

Purpose:

  Detect assumptions about the number of BIOS
  drives supported by the target system.

Notes:

  CP/M 1.4 officially supports drives:

    A: through D:

  corresponding to drive numbers:

    0..3

  CP/M 2.x systems commonly support:

    A: through P:

  corresponding to drive numbers:

    0..15

  Programs performing BIOS-level disk access
  may bypass BDOS validation and directly
  invoke SELDSK with drive numbers that are
  invalid on CP/M 1.4 systems.

  Behaviour on out-of-range drive numbers is
  BIOS-dependent and may be unpredictable.

Action:

  Verify that selected drive numbers are valid
  on the target CP/M 1.4 implementation.

Classification:

  [CHECK]

RULE E1 - RUNTIME BDOS FUNCTION DISPATCH (HINT)
-----------------------------------------------

Trigger:

  RULE A1

and one or more of:

  RULE A6
  RULE A8

Purpose:

  Centralize CP/M version-dependent BDOS
  function selection.

Notes:

  This is a possible implementation strategy.

Example (8080):

    BDOSVER:
        DB 0

    CPMREA:
        DB 0

    CPMWRT:
        DB 0

    MVI C,12
    CALL BDOS

    STA BDOSVER

    ORA A

    LXI H,1514H
    JZ INITDONE

    LXI H,2221H

INITDONE:
    SHLD CPMREA

Result:

    CP/M 1.x

        CPMREA = 14H
        CPMWRT = 15H

    CP/M 2.x

        CPMREA = 21H
        CPMWRT = 22H

Usage:

    LDA CPMREA
    MOV C,A
    CALL BDOS

or

    LDA CPMWRT
    MOV C,A
    CALL BDOS

Notes:

  Function-number dispatch tables are evidence
  of existing portability work and should be
  considered before issuing compatibility
  warnings.

Classification:

  [INFO]

RULE E2 - RANDOM ACCESS EMULATION (HINT)
----------------------------------------

Trigger:

  RULE A6

and

  No CP/M 1.x implementation is detected.

Purpose:

  Provide a possible strategy for replacing
  CP/M 2.x random-record operations.

Notes:

  CP/M 1.4 provides no equivalent of BDOS
  functions 21 and 22.

  A compatibility layer may translate an
  absolute record number into:

      extent number
      record within extent

  and use standard CP/M 1.4 sequential
  operations after selecting the proper
  extent.

Concept:

    extent = record >> 7

    record = record AND 7FH

The actual implementation may use shifts,
rotations or arithmetic depending on the
existing source structure.

Conceptual algorithm:

    extent = record / 128

    record = record MOD 128

    if extent changed then

        CLOSE current extent

        OPEN requested extent

        if OPEN fails then
            MAKE extent

    set current record

    perform READ or WRITE

Typical operations:

    CLOSE current extent

    OPEN requested extent

    MAKE extent if OPEN fails

    READ sequential record

    WRITE sequential record

Notes:

  The precise FCB offsets used for extent
  and current-record management vary among
  implementations and should be verified
  against the target source code.

  If RULE A7 is also detected, an existing
  compatibility layer may already be present.

Classification:

  [INFO]

------------------------------------------------------------------
RULE E3 - EXISTING RANDOM ACCESS EMULATION
------------------------------------------

Trigger:

  RULE A6
  RULE A7

Purpose:

  Detect probable CP/M 1.x random-access
  compatibility code.

Indicators:

      OPEN
      CLOSE
      MAKE

  combined with:

      extent manipulation

      record masking using:

          ANI 7FH

      or equivalent masking of the low
      seven bits of a record number

      extent comparisons

      OPEN/CLOSE cycles associated with
      extent changes

      extent reopen logic

Interpretation:

  Such code frequently represents an
  application-level replacement for CP/M 2.x
  random-record services.

  Typical implementations translate:

      absolute record number

  into:

      extent number
      record within extent

  and dynamically reopen extents when
  crossing extent boundaries.

Action:

  Prefer reporting the code as evidence of
  existing portability work rather than as
  a missing compatibility feature.

  If a complete extent-management layer is
  present, RULE A6 findings should be
  downgraded or correlated with the detected
  compatibility implementation.

Classification:

  [INFO]

APPENDIX:
Examples on how to get co-hexisting file access routines for
CP/M 1.4 and CP/M 2.2

;
; Detect CP/M version and initialize BDOS
; function dispatch table.
;
; CP/M 1.x:
;     BDOS Function 12 returns A = 00h
;
; CP/M 2.x:
;     BDOS Function 12 returns A <> 00h
;
; Dispatch table layout:
;
;     CPMREA = Read function
;     CPMWRT = Write function
;
; CP/M 1.x:
;
;     CPMREA = 14h
;     CPMWRT = 15h
;
; CP/M 2.x:
;
;     CPMREA = 21h
;     CPMWRT = 22h
;

        MVI     C,12
        CALL    CPMENT

        STA     BDOSVER

        ORA     A

        LXI     H,1514H          ; CP/M 1.x
                                ; L=14h READ
                                ; H=15h WRITE

        JZ      CPMVR1

        LXI     H,2221H          ; CP/M 2.x
                                ; L=21h READ RANDOM
                                ; H=22h WRITE RANDOM

CPMVR1:
        SHLD    CPMREA

        ; execution continues


;
; Storage
;

BDOSVER:
        DB      0

CPMREA:
        DB      0

CPMWRT:
        DB      0



;**** **** **** ****


;
; IMPORTANT
;
; Under CP/M 2.x:
;
;     21h = Read Random
;     22h = Write Random
;
; Under CP/M 1.x:
;
;     14h = Read Sequential
;     15h = Write Sequential
;
; Therefore this dispatch mechanism is only
; valid if an additional compatibility layer
; translates random record access into
; CP/M 1.x extent/record operations.
;

;
; Read operation
;

        LDA     CPMREA
        MOV     C,A
        CALL    CPMENT

;
; Write operation
;

        LDA     CPMWRT
        MOV     C,A
        CALL    CPMENT



;**** **** **** ****



;
; DE = absolute record number
; BC = FCB pointer
;

        LDA     BDOSVER
        ORA     A
        JZ      CPM14POS

;
; -------------------------
; CP/M 2.x
; -------------------------
;

        ; FCB+33 = RR low
        ; FCB+34 = RR high
        ; FCB+35 = RR upper

        LXI     H,22H
        DAD     B

        MOV     M,E
        INX     H

        MOV     M,D
        INX     H

        MVI     M,0

        JMP     POSDONE

;
; -------------------------
; CP/M 1.x
; -------------------------
;

CPM14POS:

        ;
        ; extent = record >> 7
        ;

        MOV     A,E
        RAL

        MOV     A,D
        RAL

        ;
        ; A now contains extent number
        ;

        PUSH    PSW

        ;
        ; Compare extent with current FCB extent
        ;
        ; (offset depends on FCB layout)
        ;

        LXI     H,0DH
        DAD     B

        MOV     E,M

        POP     PSW

        CMP     E
        JZ      SAMEEXT

        ;
        ; extent changed
        ;

        PUSH    PSW

        MVI     C,16            ; CLOSE
        CALL    CPMENT

        POP     PSW

        MOV     M,A             ; store extent

        MVI     C,15            ; OPEN
        CALL    CPMENT

        ;
        ; if OPEN failed
        ;

        INR     A
        JNZ     SAMEEXT

        MVI     C,22            ; MAKE
        CALL    CPMENT

SAMEEXT:

        ;
        ; record inside extent
        ; record MOD 128
        ;

        MOV     A,E
        ANI     7FH

        ;
        ; store current record
        ;
        ; offset implementation-dependent
        ;

POSDONE:
